# Ashfall Online

เกม MMO 2D พิกเซลบนเบราว์เซอร์ ใช้ Node.js หรือ Cloudflare Worker + Durable Object เป็นผู้คำนวณเกมกลาง และเสิร์ฟหน้าเว็บผ่าน Node, itch.io หรือ GitHub Pages

ติดตั้ง Worker ที่ `ashfall-online.phuthanet9870.workers.dev` แล้ว และเมื่อ 10 พฤศจิกายน 2026 ผ่าน [การตรวจ production HTTPS/WebSocket และเข้าโลกจริง](https://github.com/phuthanet9870-cpu/Ashfall-Online/actions/runs/42735546647) ว่าใช้ `onlineAuthority=2` การตรวจนี้ไม่แทนการทดสอบโหลดระยะยาวบน production

## ระบบออนไลน์

- เมืองและมอนสเตอร์รอบเมือง, ฟาร์ม 20 แมพ, ดันเจี้ยน, ลานบอสโลก, PvP และกิลด์วอร์ใช้ simulation ฝั่งเซิร์ฟเวอร์ ผู้เล่นในโลกเดียวกันเห็นตำแหน่ง HP สกิล กระสุน พื้นที่โจมตี ของดรอป และผลการต่อสู้ร่วมกัน
- ผู้เล่นส่งคำสั่งเดิน โจมตี ร่ายสกิล และเก็บของ เซิร์ฟเวอร์ตรวจระยะ คูลดาวน์ เป้าหมาย และคำนวณผล ไม่รับดาเมจหรือค่าสถานะที่เบราว์เซอร์ส่งมาแทนผลจริง
- ของบนพื้นเห็นร่วมกัน **ใครเก็บก่อนคนนั้นได้** ตรวจและลบเพียงครั้งเดียว กระเป๋า อุปกรณ์ เงิน รางวัล และคูลดาวน์ส่วนตัวส่งเฉพาะเจ้าของ
- PvP ใช้ผู้เล่นจริงในทีมตรงข้าม กิลด์วอร์จัดทีมตามกิลด์จริงและบันทึกผล/เรตติ้ง บอสโลกใช้บอสและอันดับดาเมจกลาง ไม่มีบอทแกล้งเป็นผู้เล่น มอนสเตอร์และยามยังเป็น NPC
- เทรดต้องอยู่ใกล้กันในเมือง ทั้งสองฝ่ายล็อกและยืนยันข้อเสนอ เมื่อแก้ข้อเสนอจะยกเลิกการยืนยันทั้งหมด การย้ายเงินและไอเทมสองฝั่งบันทึกใน transaction เดียว
- ซื้อ ขาย คราฟต์ อัปเกรด สวมอุปกรณ์ คลัง สัตว์เลี้ยง พาหนะ และกาชาใช้คำสั่งที่ตรวจเจ้าของไอเทม ราคา เงิน และ revision บนเซิร์ฟเวอร์ การส่งคำสั่งเดิมซ้ำไม่หัก/แจกซ้ำ
- สมัครบัญชีด้วยชื่อและรหัสผ่านเพื่อเล่นข้ามเครื่อง รหัสผ่านเก็บเป็น PBKDF2 hash และ session มีวันหมดอายุ การล็อกอินใหม่ยกเลิก session เดิม บัญชี guest ผูกกับกุญแจในเบราว์เซอร์ หากล้างข้อมูลจะกู้ guest เองไม่ได้
- แชท เพื่อน กระซิบ และกิลด์ทำงานร่วมกับตัวตนบัญชีเดียวกัน
- เซิร์ฟเวอร์ส่งเหตุการณ์ VFX และ seed กลาง เบราว์เซอร์วาดภาพตามเหตุการณ์ ผลการต่อสู้คำนวณบนเซิร์ฟเวอร์ โหมด gallery เป็นพื้นที่ทดลองในเครื่อง

## เซฟเดิมและข้อมูลถาวร

ตามตัวเลือกของเจ้าของเกม เซิร์ฟเวอร์รับเซฟเดิม **ครั้งเดียวต่อตัวละคร** รักษาเลเวล ไอเทม อุปกรณ์ และเงิน พร้อมเก็บ archive ของเซฟที่นำเข้า และสำรองในเบราว์เซอร์ก่อนย้าย ตัวละครเดิมหนึ่ง ID ผูกกับบัญชีที่ย้ายครั้งแรก หลังย้ายแล้วข้อมูลบนเซิร์ฟเวอร์เป็นหลัก การแก้ localStorage หรือส่ง legacy ใหม่ไม่เขียนทับตัวละครเดิม

ประวัติไอเทมก่อนย้ายตรวจย้อนหลังไม่ได้ การนำเข้าครั้งแรกจึงเป็นการเชื่อถือเซฟเดิมตามนโยบายนี้ เปิดด้วย `ALLOW_LEGACY_IMPORT=1` (ค่าเริ่มต้น) เมื่อย้ายผู้เล่นเดิมครบให้ตั้ง `ALLOW_LEGACY_IMPORT=0` เพื่อปิดรับ legacy ใหม่ บัญชีใหม่หลังปิดจะเริ่มจากตัวละครมาตรฐาน

กระเป๋าและโลกมี checkpoint ถาวร บันทึกเป็น transaction และแบ่ง/บีบอัดเอกสารให้เหมาะกับ Durable Object คำสั่งเปลี่ยนไอเทม/เงินและเก็บของบันทึกทันที โลกที่กำลังเดินบันทึกทุก 60 วินาที และบันทึกโลกที่เกี่ยวข้องทันทีเมื่อทำธุรกรรม หาก storage ล้มเหลวจะหยุด simulation แล้วลองบันทึกก่อนเดินต่อ โลกที่ว่างหยุดเดินและอาจถอดจาก cache แต่โหลด checkpoint คืนได้

การดับโปรเซสฉับพลันอาจย้อนการเดิน/ต่อสู้ถึง checkpoint ล่าสุดประมาณ 60 วินาที คำสั่งร่ายที่กำลังรอ callback ในหน่วยความจำจะถูกยกเลิกเมื่อ restart ส่วน HP ของโลก ของดรอป วัตถุประสงค์ กระสุน พื้นที่สกิล และสถานะถาวรที่บันทึกแล้วโหลดกลับได้

## รันและทดสอบ

ใช้ Node.js 20 ขึ้นไป:

```bash
npm ci
npm test
PORT=8080 npm start
```

เปิด `http://localhost:8080` หน้าเว็บบน localhost ใช้ WebSocket ของเครื่องเดียวกัน ข้อมูลทั้งหมดอยู่ที่ `data/store.json` หรือกำหนด `ASHFALL_DATA_FILE=/path/to/store.json` ต้องใช้ volume ถาวรและสำรองไฟล์นี้ ห้ามรันหลาย Node process เขียนไฟล์เดียวกัน Node flush เมื่อรับ SIGTERM/SIGINT

ทดสอบเพิ่มเติมเมื่อมี Playwright และ Chromium:

```bash
ASHFALL_TEST_URL=http://127.0.0.1:8080 node tests/browser-smoke.cjs
ASHFALL_WS_URL=ws://127.0.0.1:8080/ws node tests/load-smoke.mjs
npm run worker:dev -- --port 8788
ASHFALL_WS_URL=ws://127.0.0.1:8788/ws node tests/worker-smoke.mjs
```

`npm test` รวมกฎสกิล 750 การร่าย, โลกทุกโหมด, การแย่งเก็บของ, ความเป็นส่วนตัว, กาชา/การันตี, เทรด, session, การย้ายเซฟ, channel และการ SIGKILL/restart Node จากดิสก์จริง Browser smoke ใช้สองบริบทแยกกันเทรดผ่าน UI เข้าโหมดต่าง ๆ และล็อกอินบัญชีจากบริบทที่สาม Worker smoke ใช้ WebSocket กับ Durable Object local runtime จริง

ตรวจโหลดระยะสั้นบน Node ในสภาพแวดล้อมพัฒนาได้ 60 clients พร้อมกันประมาณ 10 วินาที ทุก client รับ snapshot ต่อเนื่อง p95 ช่วงห่าง snapshot ประมาณ 215ms ผลนี้เป็น movement smoke test ยังไม่ใช่ผลรับรองการรบเต็มรูปแบบหรือการเปิดบริการระยะยาว ควรทดสอบบนโฮสต์จริงด้วยจำนวนและรูปแบบผู้เล่นเป้าหมายก่อนเปิดสาธารณะ

Frontend/backend รุ่นนี้ใช้ `hi.features.onlineAuthority = 2` ต้องอัปเดตทั้งคู่ หาก backend ไม่รองรับจะไม่ปล่อยโหมดออนไลน์ไปจำลองต่อในเครื่อง การทดสอบใน repository ไม่ใช่การ deploy production

## ขั้นที่ 1: Deploy เซิร์ฟเวอร์ขึ้น Cloudflare Workers (ผ่าน GitHub อัตโนมัติ)
1. สมัคร/ล็อกอิน https://dash.cloudflare.com (ฟรี ไม่ต้องใช้บัตร)
2. หา **Account ID**: หน้า Dashboard → Workers & Pages → ดูที่แถบขวา "Account ID" แล้วคัดลอกไว้
3. สร้าง **API Token**: มุมขวาบน รูปโปรไฟล์ → My Profile → API Tokens → **Create Token** → เลือกเทมเพลต **"Edit Cloudflare Workers"** → Continue → Create แล้วคัดลอก token ไว้
   (token นี้เป็นความลับ ห้ามแปะในแชทหรือในโค้ด)
4. ที่ GitHub ของรีโปนี้ไปที่ **Settings → Secrets and variables → Actions → New repository secret** แล้วเพิ่ม 2 ตัว:
   - `CLOUDFLARE_API_TOKEN` = token จากข้อ 3
   - `CLOUDFLARE_ACCOUNT_ID` = Account ID จากข้อ 2
5. ไปที่แท็บ **Actions → Deploy Cloudflare Worker → Run workflow**
6. เสร็จแล้วจะได้ที่อยู่ประมาณ `https://ashfall-online.ชื่อของคุณ.workers.dev`
   - ดูได้ใน log ของ Action หรือใน Cloudflare → Workers & Pages
   - เปิด `https://ashfall-online.ชื่อของคุณ.workers.dev/health` ถ้าขึ้น `{"ok":true,...}` แปลว่าใช้ได้

## ขั้นที่ 2: บอกเกมว่าเซิร์ฟเวอร์อยู่ที่ไหน
แก้ไฟล์ `public/js/config.js` ผ่านหน้าเว็บ GitHub ได้เลย (กดไอคอนดินสอ):
```js
ws: 'wss://ashfall-online.ชื่อของคุณ.workers.dev/ws',
```
แล้วกด Commit

## ขั้นที่ 3: ลงเกมบน itch.io
1. ไปที่แท็บ **Actions → Build itch.io zip** (รันเองอัตโนมัติหลัง commit ข้อ 2) → เปิดรายการล่าสุด → ดาวน์โหลด artifact **ashfall-release** แล้วแตก ZIP ของ artifact จะได้ `ashfall-itch.zip`, `ashfall-worker.zip` และ `ashfall-source.zip`
2. ที่ itch.io → **Upload new project**
   - Kind of project: **HTML**
   - Uploads: เลือก `ashfall-itch.zip` แล้วติ๊ก **This file will be played in the browser**
   - Embed options: ขนาด 1280 × 720, ติ๊ก **Fullscreen button** และ **Mobile friendly**
3. Save แล้วตั้ง Visibility เป็น **Public** เพื่อแชร์ลิงก์ให้เพื่อนเล่น

**ทางเลือก GitHub Pages:**
1. Settings → Pages → Source เลือก **GitHub Actions**
2. Actions → **Publish game on GitHub Pages** → Run workflow
3. จะได้ลิงก์ `https://ชื่อคุณ.github.io/ashfall-online/`

## อัปเดตเกม
แก้ไฟล์ใน `public/` แล้ว commit จากนั้น
- Action จะสร้าง zip ใหม่ให้ เอาไปอัปโหลดแทนไฟล์เดิมบน itch.io
- ถ้าแก้เซิร์ฟเวอร์ (`worker/`, `server/` หรือกฎเกมใน `public/js/`) Worker จะ deploy ใหม่ให้เอง

## โฮสต์และขนาดบริการ

Worker ใช้ Durable Object storage สำหรับบัญชี ตัวละคร ธุรกรรม และ checkpoint โลก ตรวจ CPU, bandwidth, storage และโควต้าจาก Cloudflare สำหรับแผนที่ใช้จริง เกมมี simulation ต่อเนื่อง จึงไม่รับประกันว่าจะอยู่ในแพ็กเกจฟรี เมื่อเพิ่มจำนวนผู้เล่นต้องวัด CPU/latency และพิจารณาแยก authority หลาย instance

โลกสาธารณะเปิด channel เพิ่มเมื่อเต็มตาม ROOM_CAP ส่วน PvP/ดันเจี้ยนและกิลด์วอร์ใช้โลกของแมตช์ เซิร์ฟเวอร์หนึ่งตัว cache โลกได้สูงสุด 64 โลก ข้อมูลโลกที่ถอด cache ยังคงอยู่ใน storage Worker ปัจจุบันรวม authority ไว้ใน Durable Object เดียว ยังไม่ได้ทดสอบ production soak หรือหลายภูมิภาค

ก่อนเปิดใช้ ให้ deploy backend และ frontend จาก revision เดียวกัน ตรวจ `/health` และทดสอบบัญชี/เทรด/เข้าโลกจากสองเครื่อง ตั้ง TLS สำหรับ Node ที่เปิดอินเทอร์เน็ต และสำรองข้อมูลถาวร

## สร้างไฟล์ส่งขึ้น itch.io

```bash
npm ci
npx wrangler deploy --dry-run --outdir .wrangler/online-build
npm run build:itch
```

ได้ `dist/ashfall-itch.zip` (อัปโหลดเป็น HTML game โดยตรง), `dist/ashfall-worker.zip` (backend ที่ bundle แล้ว), `dist/ashfall-source.zip` (ซอร์สครบ ไม่มีฐานข้อมูลหรือ secret) และคู่มือ `dist/UPLOAD-ITCH-TH.txt`

ตั้ง backend URL อื่นได้ด้วย `python3 scripts/package-release.py --ws wss://YOUR-WORKER.workers.dev/ws` ZIP มี `index.html` อยู่ระดับบนสุด และตรวจความครบของ script/CRC พร้อมบันทึก SHA-256 ใน `release-manifest.json` ไฟล์เกมไม่รวมข้อมูลผู้เล่น

ต้องติดตั้ง backend รุ่นเดียวกันแยกจาก itch.io เพราะ itch.io โฮสต์ได้เฉพาะหน้าเว็บ ชุด Worker ใช้บัญชี Cloudflare เดิมเพื่อรักษา storage เดิม รัน `npm ci`, `npx wrangler login`, `npm run deploy` ในโฟลเดอร์ที่แตก Worker ไว้

ทดสอบ ZIP ที่แตกจริงใน iframe แบบ sandbox ด้วย `node tests/itch-package-smoke.cjs` (ต้องมี Playwright/Chromium และ Node backend บนพอร์ต 8080) การทดสอบนี้เปลี่ยนเฉพาะปลายทาง WebSocket ไปยัง backend ทดสอบ ไม่ยืนยันสถานะ production

## การเดินออนไลน์และ GM

รุ่นนี้วาดการเดินของตัวเองต่อเนื่องพร้อม collision ในเครื่อง แล้วปรับกลับตามตำแหน่งเซิร์ฟเวอร์ ส่วนดาเมจ ดรอป และคำสั่งเศรษฐกิจยังตัดสินบนเซิร์ฟเวอร์ เพิ่ม snapshot เป็นสูงสุด 10 Hz และเดิน simulation ทุก 50 ms ลดการสร้าง array/callback ในการตรวจ terrain ย้ายการบีบอัดออกจาก storage transaction และไม่คำนวณอุปกรณ์/วาดเมนูใหม่เมื่อมีเพียงเวลาเล่นเปลี่ยน

ทดสอบการเดินกับ RTT จำลอง 160 ms ด้วย `ASHFALL_TEST_URL=http://127.0.0.1:8080 node tests/motion-smoke.cjs` เทียบรุ่นเดิมบนเครื่องทดสอบเดียวกัน สัดส่วนเฟรมที่ตัวละครขยับระหว่างกดเดินเพิ่มจากประมาณ 4% เป็น 100% (74 เฟรม) เป็นการตรวจความต่อเนื่องของการเดินในสถานการณ์นี้ ไม่ใช่ผล FPS ทุกอุปกรณ์

ตามนโยบายเจ้าของเกม **ผู้เล่นที่พิมพ์ `/gmadmin2008` สามารถเปิดสิทธิ์ GM บนเซิร์ฟเวอร์สำหรับ connection ปัจจุบันได้ทุกคน** ไม่มี allowlist บัญชี ปุ่มที่แก้ข้อมูลต้องผ่านการ unlock บนเซิร์ฟเวอร์ การแก้ localStorage อย่างเดียวไม่ให้สิทธิ์ หลัง reconnect ต้องใช้คำสั่งอีกครั้ง

รองรับปรับเลเวล/คลาส/สกุลเงิน แจกไอเทมและชุดด่วน รูน แฟชั่น สัตว์เลี้ยง วาร์ปในแมพ ฮีล God/One-hit/No-CD เสกมอนสเตอร์ ดึง/ลบ/ฆ่า/หยุดมอนสเตอร์ ปรับอัตรา XP/ดรอป ประกาศ ปลดล็อกดันเจี้ยน แก้สกิล และจบแมตช์ คำสั่งโลกมีผลกับทุกคนในโลก/แชนแนลเดียวกัน คำสั่งส่วนตัวเปลี่ยนเซฟผู้ใช้คำสั่ง มี audit 200 รายการล่าสุดใน `gm-audit:v1` และบันทึกกับตัวละคร/โลกแบบ atomic คำสั่งเก่าที่พึ่งผู้เล่นจำลองหรือยังไม่รองรับจะถูกปิดในเมนูออนไลน์ โหมดแสดง VFX/gallery ยังเป็นพื้นที่ทดลองในเครื่อง

ทดสอบเมนูจริงและการเห็นมอนสเตอร์ร่วมกันด้วย `ASHFALL_TEST_URL=http://127.0.0.1:8080 node tests/gm-browser-smoke.cjs`

การส่ง snapshot ถี่ขึ้นใช้ bandwidth มากขึ้น โหลดระยะสั้น 60 clients ในเครื่องพัฒนาพบ p95 ช่วงห่าง snapshot ประมาณ 116 ms เทียบประมาณ 215 ms ก่อนปรับ ยังไม่ใช่การรับรองโหลดระยะยาวบน production

## รักษาหน้าต่างและรูปแบบเกมเดิม

งานออนไลน์ต้องใช้หน้าต่าง ตัว renderer, CSS, แท็บ เมนู ไอคอน และปุ่มของเกมเดิม เพิ่มเฉพาะการเชื่อมคำสั่งและข้อมูลกับเซิร์ฟเวอร์ ห้ามสร้างหน้าต่างใหม่มาทดแทนหรือปรับกติกา/ค่าพลัง/ไอเทม/เลเวล/รางวัลโดยไม่ได้รับคำสั่งจากเจ้าของเกม

หน้าต่างเทรดใช้ `UI.PANELS.trade` จาก `trade.js` ตามเดิม ทั้งรูปตัวละคร ช่องไอเทม 8 ช่องต่อฝั่ง กระเป๋า ช่องทอง ล็อก/ปลดล็อก/ยืนยัน ผู้เล่นใกล้เคียง และประวัติ `online-trade.js` ทำหน้าที่เชื่อมข้อมูลและคำสั่งเท่านั้น กระเป๋าอีกฝ่ายยังเป็นส่วนตัวและส่งเฉพาะไอเทมที่เจ้าตัวเสนอ ไม่มีการเลือกแทนอีกฝ่าย

HUD ของ PvP/กิลด์วอร์และหน้าต่างผล PvP/กิลด์วอร์/ดันเจี้ยนใช้ renderer เดิม รับข้อมูลผลจากเซิร์ฟเวอร์ ปุ่มลัดโลกออนไลน์ หน้าต่าง multiplayer และแถบสถานะที่เพิ่มแยกถูกนำออก ใช้เมนูและสถานะออนไลน์เดิมของเกม

## โควตาฐานข้อมูล Cloudflare

เมื่อ 9 พฤศจิกายน 2026 การทดสอบบน production พบ `Exceeded allowed rows written in Durable Objects free tier.` จึงเพิ่มการตรวจ guest auth, เข้าโลกสองผู้เล่น, การเดินที่อีกฝั่งเห็น และการซื้อของส่วนตัวในทุก deployment หลังตรวจ HTTPS/WebSocket

ระบบข้ามเอกสารที่ไม่เปลี่ยน ใช้ chunk ขนาดใหญ่ขึ้นภายในขีดจำกัด 128 KiB บันทึก snapshot โลกทุก 60 วินาที และไม่เขียนโลกอื่นเมื่อทำธุรกรรมในโลกเดียว กระเป๋า/การเก็บของ/เทรดยัง commit ทันทีเป็น transaction เมื่อฐานข้อมูลปฏิเสธจะถอยช่วง retry สูงสุด 60 วินาที แผน Free ยังมีเพดานรายวันซึ่ง [Cloudflare รีเซ็ตเวลา 00:00 UTC หรือ 07:00 น. ไทย](https://developers.cloudflare.com/durable-objects/platform/pricing/)
